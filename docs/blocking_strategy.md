# Blocking Strategy

Implemented in `src/blocking.py`. Blocking determines the maximum achievable
recall for everything downstream, so it is measured before the matcher is
optimized (Section 6).

## Views
1. Exact normalized name
2. Name token overlap
3. Character n-gram retrieval (shared-trigram count)
4. Address token retrieval
5. Address character n-gram retrieval
6. TF-IDF (char n-gram) nearest-neighbor retrieval over name+address
7. Embedding retrieval -- left as an extension point, not implemented by
   default (would require an embedding model within the licensing/size
   constraints; not needed until the above passes are shown insufficient)

## Marginal utility accounting
`src/blocking.py::marginal_recall` computes, per pass and in a chosen order:

    delta_R_k = R(C1 union ... union Ck) - R(C1 union ... union C_{k-1})

alongside `AvgCand`, `P95Cand`, and (in `reports/blocking_experiments.csv`,
generated by the notebook/script that calls this function against the
leakage-safe validation split) runtime. A pass is retained only when its
recall contribution justifies its candidate cost, or it protects a
difficult, systematically under-covered case (e.g. transliterated names,
which the exact/token passes miss but the character n-gram pass often
catches).

## Country handling
No blocking pass filters or keys on country. Country is used only as a
downstream *feature* (`country_agreement`, `country_unknown` in
`src/features.py`), so a country introduced only at test time (France) still
gets full candidate coverage from the name/address passes.
